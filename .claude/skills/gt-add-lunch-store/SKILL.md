# add-lunch-store

市ヶ谷ランチマップ（`gt-lunch-map` リポジトリ）に店を **1件** 追加するためのスキル。
対象は2マップ：**ランチ**＝`data/restaurants.csv`（ID `LU0xx`）／**居酒屋**＝`data/izakaya.csv`（ID `IZ0xx`）。両者は同一スキーマ。

作業ディレクトリはこのリポのルート（`build.sh` がある場所）で行う。外向き操作（push/Pages）はしない。

## 全体の流れ

1. **対象マップを確認**（未指定なら聞く）：`lunch` か `izakaya` か。
2. **同定・住所・ジャンルを調べる**（Web検索）
3. **正確な座標を取る**（店舗ページの埋め込み座標）
4. **大分類を決める**（無ければ「その他」。新設は下記手順）
5. **評価・感想を質問形式で聞く**（勝手に埋めない）
6. **行を追記 → build**（下記 §6 の `add_row.sh` を絶対パスで実行。スクリプトはリポ直下ではなく `.claude/skills/gt-add-lunch-store/scripts/` にある）
7. **報告＋要確認**

調べて埋めるのは「店名・住所・座標・大分類」だけ。**評価と感想は必ずユーザーに聞く**（主観情報なので調べられない）。

## 各ステップ詳細

### 2. 同定・住所・実ジャンル
店名で Web 検索し、市ヶ谷周辺の実在店に一致させる。手書き・通称のことがあるので **正式店名** を確定する。
- 出典：食べログ / ホットペッパー / ぐるなび / Retty / 公式サイト
- 取るもの：正式店名、**住所（丁目-番-号まで）**、実ジャンル（数語）、ビル名・階（あれば）
- 同定が曖昧・別支店の可能性がある場合は要確認に回す。

### 3. 正確な座標
**Yahoo!マップの place ページ**（`map.yahoo.co.jp/v3/place/...`）または食べログ店舗ページを開き（WebFetch）、埋め込まれた **緯度・経度** を抽出する。
- **GSI の住所検索は使わない**（番地の中心に丸められ 100m 以上ずれる）。
- 検算：緯度 `35.68〜35.70` / 経度 `139.73〜139.745` に入るか。外れたら信頼度低として要確認。
- CSV は `lat`=緯度・`lng`=経度。**多くのソースは (経度, 緯度) の順なので入れ替え注意。**

### 4. 大分類
対象マップの大分類から1つ選ぶ。該当が無ければ空欄（表示側で「その他」）。
`大分類` 列の値は下の正式名と**完全一致**させること（一致しないと色が付かない）。
- **ランチ**：`麺類` / `肉` / `魚・海鮮` / `和食・定食` / `中華` / `エスニック・カレー` / `洋食・カフェ`
- **居酒屋**：`焼き鳥・串` / `魚介・海鮮` / `焼肉・ホルモン` / `和食・小料理` / `中華・餃子` / `バル・ワイン`

既存に合わない店が **複数** 見込まれる時だけ新設（→「新しいジャンルを追加する」）。1店だけなら「その他」に寄せる。
店の丁目が既存の地域に無ければ →「新しい地域を追加する」。

### 5. 評価・感想を質問形式で聞く
調べても分からない主観情報。**まとめて1回で質問し、回答を待ってから** 6 に進む。勝手に埋めない。
各項目に**スケールの意味を必ず添え**、「だいたいでOK・分からなければ空欄でOK」と伝える（唐突に「安さは？」だけ聞かない）。

- まず **訪問済みか？**（**未訪問なら評価・感想は空でよい**。この場合は評価を聞かずに進む）
- **美味しさ**（1〜5、5=とても美味しい）
- **量**（1〜5、5=とても多い）
- **安さ**（1〜5、**5=安い（＝お得・割安）** / 3=普通 / 1=高い。※この内容でこの値段は安いか＝コスパ観点）
- **感想**（自由・任意）／**備考**（自由・任意）

質問例：「（訪問済みなら）ざっくりで大丈夫です。美味しさ・量・安さを各1〜5で。安さは5=安い/1=高い。感想もあれば。分からない項目は空欄でOKです。」

### 6. 行を追記 → build
> **このスキルの scripts はリポの `.claude/skills/gt-add-lunch-store/scripts/` にある**（実行時のカレントはリポルート）。
> どこから呼んでも見つかるよう、以下は git ルート経由で呼んでいる。

`店舗ID` は次の連番。取得は:
```
bash "$(git rev-parse --show-toplevel)/.claude/skills/gt-add-lunch-store/scripts/next_id.sh" lunch     # → 例 LU046
bash "$(git rev-parse --show-toplevel)/.claude/skills/gt-add-lunch-store/scripts/next_id.sh" izakaya   # → 例 IZ002
```
列は固定順（16列）：
```
店舗ID,店名,地域,カテゴリ,場所,住所,lat,lng,美味しさ,量,値段,感想,備考,更新者,訪問済,大分類
```
- `更新者` は **実名を書かない**。ニックネーム（例 `katyoid` / `F`）。
- `値段` 列＝安さ。`カテゴリ` は実ジャンルの原文（例「焼き鳥」）。`大分類` は §4 の正式名。
- 文字列フィールドは `"..."` で囲む。未入力（評価・感想など）は `""`。

追記＋ビルドは:
```
bash "$(git rev-parse --show-toplevel)/.claude/skills/gt-add-lunch-store/scripts/add_row.sh" <lunch|izakaya> '<CSV1行ぶん>'
```
このスクリプトが対象CSVに append し（**BOM は先頭のみで触らない／上書きしない**）、`bash build.sh` まで実行する。

**行の例（居酒屋・串八珍）**：
```
IZ001,"串八珍","五番町","焼き鳥","五番町グランドビル 1F","東京都千代田区五番町3-1",35.690456,139.735913,"4","4","4","炭火焼き鳥。夜は居酒屋づかい","","katyoid","訪問済","焼き鳥・串"
```

### 7. 報告
追加した店の要点（ID・店名・地域・大分類・座標）と、**要確認リスト**（同定が曖昧／座標が範囲外／新地域や新ジャンルを作った 等）を短く。ターミナルに長文を貼らない。

## 新しい地域（丁目）を追加する
店の住所の丁目が既存の地域に無いとき。
1. 住所から正式な丁目名を確定（例 `三番町`、`九段北四丁目`）。
2. 丁目境界を取得して `data/area_polygons.json` に追記（hover の縁取り用）：
   ```
   curl -sG "https://uedayou.net/loa/$(printf '%s' '東京都千代田区三番町' | jq -sRr @uri).geojson" \
     | jq -c 'if .geometry.type=="MultiPolygon" then .geometry.coordinates[0][0] else .geometry.coordinates[0] end
              | [.[]|[((.[1]*1000000|round)/1000000),((.[0]*1000000|round)/1000000)]]'
   ```
   得られた配列（**[緯度,経度] に変換済み**）を、`data/area_polygons.json` に **キー=表示名と一致する丁目名** で追記する（値は `[ring]` の形。丁目分割のある町は該当丁目を取得し、複数なら `[ring1, ring2]`）。
3. `bash build.sh`。
- **制限**：市ヶ谷駅周辺（概ね 緯度 35.68–35.70 / 経度 139.73–139.745 に入る丁目）に限る。名称は住所の正式表記どおり。境界が取れない丁目はポリゴン無しでも可（hover 縁取りが出ないだけで動作はする）。

## 新しいジャンル（大分類）を追加する
既存に合わない店が **複数** 見込まれるときだけ。1店なら「その他」。
1. `src/template.html` の `MAJORS_BY_DS["lunch" or "izakaya"]` に `{g:"名称", label:"◯", color:"#xxxxxx"}` を追加。
2. CSVの `大分類` 列にその `g`（正式名）を **完全一致** で入れる。
3. `bash build.sh`。
- **制限**：`label` は日本語1文字／`color` は既存と十分に異なる濃い色（白文字が乗る）／`g` は CSV 値と完全一致・表記ゆれ禁止／**単発ジャンルは作らない**（2店以上の見込みがある時のみ）。数の上限は無し。

## ガードレール
- 外向き操作（`gh` / push / Pages）はしない。ローカルの CSV 追記＋ build まで。
- **既存行を書き換えない**（追記のみ）。同名の既存店があれば重複を確認。
- 公開ページ方針：会社名・部署名・個人名・勤務地を出さない（`更新者` はニックネーム）。
- 座標は必ず範囲チェック。外れたら投入せず要確認に回す。
- BOM は各CSVの先頭のみ。append で触らない。
