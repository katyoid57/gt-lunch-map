# 座標（lat/lng）の入れ方

`data/*.csv` の `lat`（緯度）/ `lng`（経度）を埋めると地図にピンが立つ。空でもページは動く（一覧には出て、Google Maps リンクも機能する）。

**通常は skill `gt-add-lunch-store` が自動でやる**（店を1件足すたびに、Web検索で住所を特定 → 店舗ページから正確な座標を取得 → CSV追記 → build）。ここは仕組みと、手で直したいときのメモ。

## 座標の取り方（skill と同じ方針）

1. 店名で Web 検索し、正式店名・住所を特定。
2. **Yahoo!マップの place ページ**（`map.yahoo.co.jp/v3/place/...`）または食べログ店舗ページを開き、**埋め込まれた緯度・経度**を取る（店舗ピンレベルで正確）。
3. `lat`=緯度・`lng`=経度で CSV に記入。

> **GSI の住所検索 API は使わない。** 番地の中心に丸められ、番町エリアでは 100m 以上ずれる（No.4 で実測 ~180m）。住所→座標ではなく、店舗ページの実座標を使うこと。

## 検証（外れ値の見つけ方）

市ヶ谷駅周辺なら概ね次の範囲。外れたら要確認：
- 緯度 `lat`：約 **35.68 〜 35.70**
- 経度 `lng`：約 **139.73 〜 139.745**

## CSV フォーマットの注意

- `lat`=緯度（例 `35.694103`）、`lng`=経度（例 `139.739426`）。小数6桁もあれば十分。
- **順序の罠**：多くのソース（GeoJSON・KML・GSI）は座標を **(経度, 緯度)** の順で返す。CSV 列は `lat, lng`（緯度, 経度）なので**入れ替えて**入れる。
- 座標が両方空 → ピンは出ず一覧にだけ表示（リンクは機能）。片方だけ入れるのは避ける。
- 同一住所（同ビル）の店は、表示上だけ円状にずらして重なりを防ぐ（CSV の値は真値のまま）。
- 編集後は必ず `bash build.sh`。カウンタの「座標未設定 M 件」で進捗が分かる。

## 手で1件だけ直す（Google Maps）

正確に直したい少数はこれが早い：
1. Google Maps で店を検索 → 目的地を**右クリック** → 先頭の「`35.6xxxx, 139.7xxxx`」をクリックでコピー。
2. 該当行に貼る（**カンマ前が緯度=`lat`、後が経度=`lng`**）→ `bash build.sh`。
